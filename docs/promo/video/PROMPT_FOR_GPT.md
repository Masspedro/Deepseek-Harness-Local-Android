## 叙事结构（骨架给你，分镜你自己设计）

**核心洞察：短视频要赢在前 3 秒。** 不要用 logo 动画开场，那是浪费。

建议的叙事弧（你可以改，但要保持这个张力结构）：

1. **钩子（0~4s）**：先制造「不可能」的认知。屏幕上打出「在 Android 上跑完整 Node Agent 引擎」，
   然后**数秒内**直接切到冷启动实拍 + 倒数计时。让观众亲眼看到 3 秒。
2. **它凭什么快（4~14s）**：这里是全片的技术心脏。用**代码画的对比动效**讲清「没有中间层」：
   - Termux 路线：一条长长的链（Perl → apt → env → Node），逐节点亮起，总耗时「分钟级」
   - proot 路线：内核 → proot → glibc → 发行版 → Node，同样长链，「十几秒，部分设备起不来」
   - **DSH Mobile**：一条**直线**，一个箭头直达 Node，标「3.4 s」
   - 视觉上要让「长链」与「直线」形成强烈对比。这是全片最该记住的一帧。
3. **它能干什么（14~28s）**：能力快闪。用真实截图 + 你画的手机框，快速但清晰地展示：
   21 项扩展、3540 个插件、真 PTY 终端、无障碍控制、SSH 远程、桌宠。
   **每个能力只给 1.5~2.5 秒**，靠节奏不靠时长。关键数字用数字滚动动效砸出来。
4. **可信度（28~36s）**：讲工程深度。14 个 Android 补丁、581 行 C 写的 PTY、
   两阶段提交换装、16 项回归探针。这一段要「冷静、硬核」，配色收一点，靠代码感的排版取胜。
5. **收尾（36~42s）**：回到品牌。`DeepSeek Harness. Now in your pocket.` +
   `No Root · No Termux · No PC` + 下载入口二维码或链接。

**字体**：英文/数字 Segoe UI（Bold 做标题、Light 做大号数字），中文微软雅黑，
终端画面用 Consolas。**大号数字必须等宽**，避免动画时抖动。

**构图**：竖屏 1080×1920（9:16）为主，同时导出横屏 1920×1080 版本。
竖屏确保底部 15% 无关键信息（避开平台 UI）。

**动效原则**：

- 毫不吝啬使用 **物理感曲线**（spring、overshoot），但**幅度要小**——高级感来自克制
- 一切进场都有**方向逻辑**（从哪来到哪去），不要随机淡入
- **每个关键数字都要用滚动/计数动效**，不要静态出现
- 背景永远有**极缓的流动**（渐变呼吸 / 细粒子 / 网格缓移），避免死板
- 转场用**速度模糊 + 方向推进**，不要用花哨的 3D 翻转

1. **Remotion**（最新稳定版）+ TypeScript + React
2. **每帧代码绘制**：所有视觉元素是 React 组件。可用 CSS、SVG、Canvas（`@remotion/…` 生态）、

6. 输出：`1080×1920` 与 `1920×1080` 两个 composition
7. 60fps
8. 单文件组件不要超过 300 行，超过就拆

## 两个必须自己想清楚的设计难题

**难题一：3.4 秒怎么拍？**

冷启动真实录屏有 28 秒（含解压）。直接变速会显得仓促、也看不清。你的选择可能是：
变速 + 关键时刻定格放大、或干脆用代码重绘一个「压缩版启动时间线」（进度条 + 阶段标签 + 秒数跳动）。
两条路都行，但**必须让观众相信这是真实数据**，而不是随便打了一个数字。想清楚用什么视觉语言建立这种可信度。

**难题二：技术深度怎么讲才不无聊？**

「14 个补丁」「581 行 C」「两阶段提交」这些是全片最有含量、也最容易让观众划走的部分。
你不能只是把文字打出来。考虑用：代码流水的视觉化、补丁逐个"命中"的动效、
或者把「两阶段提交」画成一个有明确状态机的示意图。**要让不懂技术的人觉得酷，让懂的人觉得对。**
