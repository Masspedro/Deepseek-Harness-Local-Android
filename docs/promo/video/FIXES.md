## 体检范围与判定口径

- 成片：竖屏 1080×1920、60 fps、44 秒；每秒检查帧为 `秒数 × 60`，共 44 帧。
- 基线证据：逐秒渲染帧位于 `remotion/out/baseline-44/element-0000.png` 至 `element-2580.png`；44 帧联系表为 `remotion/out/baseline-44/contact.png`。另对 10、13、14、16、17、18、25、26、29、30、31 秒关键帧作了全尺寸查看。原始抽查帧为 `review-frames/f02.png` 等 16 帧及 `_all.png`。
- 竖屏平台安全区：顶部 12% = y 0–230 px；底部 18% = y 1574–1920 px；左右 6% = x 0–65 / 1015–1080 px。关键文案、数字、截图不应进入这些带区。
- 下列像素为渲染帧上的约值（四舍五入到约 5–10 px）；“重叠高度”按可见内容框相交估算，不把纯背景渐变或彼此错开的淡入效果当成内容重叠。

## 归纳的根因

1. `src/ui.tsx` 的旧 `Stage` 使用 `paddingTop: 20%` / `paddingBottom: 18%`；CSS 百分比内边距按包含块宽度计算，在 1080px 竖屏宽度上约为 216px / 194px，不能表达要求的 230px / 346px 画布安全区。当前版本改为固定像素 insets（230/346/65）。
2. 旧 `ChapterBar` 使用 `bottom: 8%`，在 1080px 竖屏宽度上约为 86px，顶边约 y=1831；它仍落在底部 UI 带内。当前版本使用独立安全区通道，章节线位于安全区内。
3. `ScaleScene` 和 `DepthScene` 将时间段内容放进满屏 `AbsoluteFill` / `Sequence layout="absolute-fill"`，用绝对填充覆盖外层流布局；大字、图表卡和常驻标题分别排版，未做高度预算。
4. Scale 每行文字与数值跟柱条一起延迟淡入，三个图组切换时产生空卡片；卡片使用固定大间距，8 行 + 两个注释在 portrait/landscape 未分开预算。
5. Ecosystem 用 `flex:1` 保留原尺寸 420px 手机图（截图高约 933px），但标题、3540、扩展说明及底部免责文本也在同一纵向流中；截图最小高度大于剩余空间，默认 flex shrink 不能解决绝对尺寸冲突，最终与两处说明重叠并进入 UI 带。
6. Depth 将全尺寸 `AbsoluteFill` 星点场作为背景，却把文字也居中压到点阵中心；`54` 阶段内容堆在同一区域，且数字计数从 0 延迟开始，形成“0 + 星点 + 统计行”的争抢。
7. Path 的 `execve()` 绝对定位到路线标题上方；路线节点文字按延迟渐入，造成首秒空卡及路线标签挤压。
8. Root 的场景交叉淡入淡出允许两场内容在切点重叠 18 帧；这是动画策略本身，不符合“内容不互相压叠”的要求。

## 修复方案（实施中）

- Stage 改按竖屏 12%/18% 与横屏 5%/5% 安全边距；底部章节条放入安全区上沿。
- Root 改成精确连续的 7 段硬切（场景内部淡入保留），不再同时绘制两场内容。
- Path 将 `execve()` 改为路线内联元素；路线名称/节点立即可见，仅连接线渐入。
- Scale 每个组改用普通文档流；分组标题与副标题增加间距；行标签/数值从首帧可读、柱条单独增长；portrait/landscape 各自压实卡片行高并验算总高。
- Ecosystem 竖屏按可用高度计算截图宽高，横屏使用文字与手机截图并排的 flex 布局；说明与手机框保持互斥区域。
- Depth 把模块文字、统计与星点图分区排布，不再重叠；移除常驻重复脚注，模块/PTY 两段各自位于安全内容区。
