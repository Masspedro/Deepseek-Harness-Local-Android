## 四点五、竞品对比数据（v1.4.36 时期实测，用于对比图）

> ⚠️ **重要前提**：与同类「bionic 直跑」型移植版相比，**功能能力基本相同**
> （都是官方 dsh 引擎 + 自己的运行时）。所以对比**不要放在功能清单上**，
> 那会显得刻意。真正站得住的差异只有两项：**冷启动速度** 与 **架构路线**。

### A. 安装包体积 vs 首次总下载量（**两个口径必须分开画**）

> ⚠️ **这是本片最容易翻车的地方，务必看清。**
>
> 我们的「简单包」只有 24 MB，但**首次启动还要再下载 128 MB 运行时**，
> 所以**首次总下载量约 152 MB，与完整包（149 MB）几乎一样**。
> 把 24 MB 拿去和别人比是不公平的 —— 那只是「安装那一刻的下载量」，
> 不是用户真正付出的流量。**两个口径必须分两组柱子画。**

#### 口径一：安装包体积（用户点下载时的大小）

| 产品 | APK | 需二次下载 | 首次总下载 |
|---|---|---|---|
| dphmoblie 0.3.5（proot + Ubuntu） | **392 MB** | 否（内嵌） | 392 MB |
| DSHA 0.2.1-rc.2（proot） | **279 MB** | 否（内嵌） | 279 MB |
| woaiys3 1.20.0（bionic） | 155 MB | 否（内嵌） | 155 MB |
| **DSH Mobile 完整包** | **149 MB** | **否** | **149 MB** |
| guzhou079 1.42.13（bionic） | 118 MB | 否（内嵌） | 118 MB |
| DSHBox 1.5.0（Termux 快照） | 112 MB | 否（内嵌） | 112 MB |
| dsh-phone-root 0.2.11 | 41 MB | **是（需另装 Termux App）** | 41 MB + Termux |
| **DSH Mobile 简单包** | **24 MB** | **是（首启下载 128 MB）** | **≈152 MB** |

#### 口径二：首次可用总下载量（用户真正付出的流量）

按上表最后一列排：

- dphmoblie **392 MB**
- DSHA **279 MB**
- **DSH Mobile（任一包）≈150 MB**
- woaiys3 155 MB
- guzhou079 118 MB
- DSHBox 112 MB
- dsh-phone-root 41 MB + Termux App（体积视 Termux 版本）

**诚实结论**：
- 我们**不是下载量最小的**（DSHBox 112 MB、guzhou079 118 MB 都更小）
- 我们与 woaiys3 基本持平（149 vs 155）
- 我们的优势是**与 proot 类方案相比体积小一半以上**（149 vs 279/392），
  且**不需要第二次下载**（简单包除外）

#### 口径三：解压后占用（安装完成后磁盘占用）

| 产品 | 解压后 | 备注 |
|---|---|---|
| **DSH Mobile** | **404 MB** | 运行时（14572 文件）|
| guzhou079 | 370 MB | payload 解压 |
| DSHA | 440 MB | runtime 解压 |
| woaiys3 | 462 MB | payload 解压 |
| dphmoblie | **1297 MB** | **含完整 Ubuntu 发行版（glibc）** |
| DSHBox | 未知 | zstd 压缩，未解压验证 |

> dphmoblie 的 1.3 GB 是「完整发行版」的直接代价 —— 这是三个口径里差距最大的一项，
> 也是「只装 dsh 真正需要的东西」这个设计选择最直观的变现。

### A2. 路线差异（可从 APK 结构验证，与体积独立）

| 产品 | 载体 | 路线 | 额外层 | 含 glibc |
|---|---|---|---|---|
| **DSH Mobile** | 自建 bionic 运行时 | **bionic 直跑** | **无** | 否 |
| guzhou079 | payload.zip | bionic 直跑 | 无 | 否 |
| woaiys3 | payload.zip | bionic 直跑 | 无 | 否 |
| DSHA | dsh-runtime.bin (gz+tar) | proot + rootfs | proot 用户态翻译 | 否 |
| dphmoblie | rootfs.bundle (gz) | proot + Ubuntu | proot + glibc + 发行版 | **是** |

| dsh-phone-root | termux.apk | 引导装 Termux | 需二次安装 App | 未知 |

**可上屏的结论**：
- 同类 bionic 路线有三家（我们 / guzhou079 / woaiys3），**功能能力基本相同**，别比功能

- dphmoblie 1297 MB vs 我们 404 MB —— 「完整发行版 vs 只装需要的」

### A3. 原生外壳的完整度（**这是我们真正的优势，且可验证**）

用户说「用了十几款，就这款最好」。查下来不是错觉 —— 各家都能把 dsh 引擎跑起来
（这部分是上游的），但**帮引擎干活的原生外壳**厚度差了一个量级。

#### 指标一：原生代码体量（dex 大小，客观可测）

| 产品 | dex 大小 | 相对本作 |
|---|---|---|
| DSHA | 17.1 MB | 1.8× （含 proot 全家桶） |
| **本作** | **9.3 MB** | 1× |
| DSHBox | 10.3 MB | 1.1× （含 proot 全家桶） |
| dphmoblie | 2.0 MB | **0.2×** |
| guzhou079 | 0.7 MB | **0.08×** |
| woaiys3 | 0.6 MB | **0.06×** |

> 注意：DSHA / DSHBox 的 dex 大是因为打进了 proot 相关的 Java 层，
> 不代表原生功能多。真正可比的是同为 bionic 路线的 **guzhou079 0.7 MB /
> woaiys3 0.6 MB vs 本作 9.3 MB —— 差 15 倍**。

#### 指标二：自有原生库

| 产品 | 自有 so | 说明 |
|---|---|---|
| **本作** | `libdsh_pty_exec.so` `libdshpty.so` `libtermux.so` `libmlkit_google_ocr_pipeline.so` | **自写 PTY 助手 + 自带 OCR** |
| dphmoblie | `libdsh_proot.so` `libdsh_proot_loader.so` `libdsh_pty.so` | proot 加载器 + pty |
| DSHA | `libdsha-proroot-*.so` `libdsha-session.so` | proot 兼容层 |
| DSHBox | `libproot.so` `libproot-loader.so` | proot 全家桶 |
| guzhou079 | **无自有 so** | 纯 Java 外壳 |
| woaiys3 | **无自有 so** | 纯 Java 外壳 |

#### 结论：可以放心说的优势

1. **原生外壳厚 15 倍**（9.3 MB vs 0.6-0.7 MB dex）—— 用户感知到的「好用」来自这里：
   这不是「多塞了功能」，而是**每个环节都做了原生实现**（PTY 自己写 C、OCR 自己接、
   SSH 自带、无障碍闭环自己做）
2. **10/10 能力覆盖**，竞品最多 5/10
3. 榜单里唯一同时具备：自有 PTY + 内置 SSH + 自带 OCR + 桌宠 + 扩展中心 + 插件市场

> ⚠️ 仍然要守住的底线：这张表是**下界估计**，文案里应写「我们的实现覆盖 10 项，
> 抽查的竞品覆盖 3-5 项」，**不要**写成「他们没有这些功能」——只能说
> 「在我们检查的版本里没找到实现痕迹」。

| **插件与扩展** | 7 | 扩展中心（21 项）、社区市场（3540）、兼容性分级、插件自愈隔离、应急总开关、hardssh 安装器 |
| **会话与数据** | 7 | 崩溃恢复、zstd 多帧解压、会话尾部读取、对话完成检测、导入导出、**场景记忆** |
| **无障碍与视觉** | 8 | 闭环执行器（21 原语）、快速决策层、**视觉追踪**、**帧差验证**、页面状态识别、OCR、图标匹配、悬浮状态条 |
| **语音** | 7 | 离线 ASR、云端 ASR、EdgeTTS、TTS 管理、语音桥、面板、本地模型 |
| **网络与远程** | 6 | 局域网 WebUI 代理、Shizuku HTTP 桥、WebView 下载器、凭据探测、更新检查 |
| **终端** | 3 | 原生 PTY、PTY 会话管理、终端页 |
| **桌宠** | 7 | 悬浮服务、动画链、物理引擎、移动规划、台词库、资源包下载、桥接协议 |

**几个之前完全没上屏、但很硬的点**：

- **场景记忆（SceneMemory）**：「越玩越聪明」—— 记住成功路径，下次同样场景直接走
- **视觉三层兜底**：无障碍树 → 视觉追踪（VisionTracker）→ 帧差验证（Framer）。
  任何一层缺失（ColorOS/游戏拿不到节点树）都还能工作
- **快速决策层（FastPicker）**：「非黑即白判断题」架构，把模糊判断压成确定性选择
- **zstd 多帧解压（ZstdTail）**：dsh 的会话是 zstd 多帧格式，普通库解不了
- **孤儿进程回收（OrphanReaper）**：AI 起的进程没销毁会阻塞，自动回收
- **Profile 守护（ProfileGuardian）**：插件配置 YAML 被写坏会让引擎起不来，自愈层

### A5. 实测性能（2026-10-28，Android 16 x86_64 模拟器 / 2.5 GB 内存）

> ⚠️ 模拟器数据，**非真机**。真机数据见 B 节（3.4 秒来自一加 15T 实测）。
> 模拟器跑 x86_64 + 软件渲染，比真机慢，这里的数据用于**横向比较自身波动**。

| 指标 | 实测值 | 说明 |
|---|---|---|
| 冷启动 `am start -W` TotalTime | **3.1 / 3.6 / 5.1 秒**（3 次） | 中位 3.6 s，模拟器 |
| 稳态 PSS（App 主进程） | **112 ~ 118 MB** | 引擎就绪后 25 s 采样 |
| App 进程 RSS | **272 MB** | 含 WebView 共享段 |
| node 引擎进程 RSS | **154 MB** | 独立进程 |
| 进程总数 | **1 个 App 进程** | 引擎是其子进程，非独立 App |
| 线程数 | **65** | 引擎就绪稳态 |

**口径说明（重要）**：安卓内存有四种口径，容易互相打脸。
- **PSS**（112-118 MB）：分攤共享页后的「相当于独占多少」
- **RSS**（272 MB）：真实物理页，含共享库
- 别家说自己「占 200MB」可能是 PSS，也可能是 RSS，**跨产品比较必须同口径**
