## 四点五、竞品对比数据（v1.4.36 时期实测，用于对比图）

> ⚠️ **重要前提**：与同类「bionic 直跑」型移植版相比，**功能能力基本相同**
> （都是官方 dsh 引擎 + 自己的运行时）。所以对比**不要放在功能清单上**，
> 那会显得刻意。真正站得住的差异只有两项：**冷启动速度** 与 **架构路线**。

### A. 路线差异（客观可从 APK 结构验证）

| 产品 | 载体 | APK 体积 | 路线 | 额外层 |
|---|---|---|---|---|
| DSH Mobile（本作） | 自建 bionic 运行时 | 149 MB | **bionic 直跑** | **无** |
| guzhou079 v1.42.13 | `payload.zip` | 118 MB | bionic 直跑 | 无 |
| woaiys3 v1.20.0 | `payload.zip` | 155 MB | bionic 直跑 | 无 |
| DSHA v0.2.1-rc.2 | `dsh-runtime.bin` | 279 MB | proot + rootfs | proot 用户态翻译 + glibc |
| DSHBox v1.5.0 | `dsh/*.tar.zst` | 112 MB | Termux 快照 | 解压 rootfs + 路径重定位 |
| dphmoblie v0.3.5 | `runtime/rootfs.bundle` | **392 MB** | proot + Ubuntu | proot + glibc + 完整发行版 |
| dsh-phone-root v0.2.11 | `termux.apk` | 41 MB | 引导装 Termux | 需二次安装 App |

**可上屏的结论**：
- 同类 bionic 路线（我们 / guzhou079 / woaiys3）**体积相当**（118–155 MB），不构成优势，别比
- 与 proot/快照路线相比：**少一层用户态翻译**，这是启动快的结构性原因
- dphmoblie 392 MB vs 我们 149 MB —— 这是「完整发行版 vs 只装需要的」的直接体现

### B. 冷启动（本作实测，竞品暂无同条件数据）

| 设备 | 冷启动 |
|---|---|
| 一加 15T / Android 16 | **3.4 秒** |
| 主流中端机 | **5 ~ 6 秒** |
| 紫光展锐手表 / 3 GB 内存 | **13 秒** |
| 模拟器 x86_64 / 2.5 GB | **2.2 ~ 2.7 秒** |

> ⚠️ **诚实边界**：我们没有在**同一台设备、同一测量方法**下测过竞品的冷启动。
> 视频里**不得**出现「竞品启动要 X 秒」这类未实测的并列柱状图 —— 那是编造。
> 可以对比的是**架构层数**（可验证），以及**陈述我们自己的实测数字**。
>
> 若要做竞品启动对比图，必须满足：同一设备、同一 `am start -W` 方法、各 3 次取中位、
> 在 CHECKLIST 里附原始数据。没测就不画。

## 五、文案（已定稿，可直接用）

### 主张

- 主标语：**DeepSeek Harness. Now in your pocket.**

- ❌ 完全离线大模型
- ❌ 所有数据永不离开设备（模型请求会出设备，取决于用户配置的 API）
- ❌ 任何「破解」「绕过」「越狱」类暗示
- ❌ 宣称支持 iOS / 桌面（本项目只做 Android）

`chat-attempt1/2.mp4` 里消息**没有真正发出**：输入框已清空、点过发送按钮，但会话未落盘、界面无回复。

**已排除**：
- 网络：引擎侧 `curl https://api.deepseek.com/` 返回正常 JSON（`Authentication Fails (missing key)` 说明链路通）
- API key：已在界面填入并保存（掩码显示，未泄漏）

**未定位**：WebView 侧发送动作是否真正触发。可能是 release 包（`targetSdk 28`）+ 模拟器 WebView 的组合问题，需单独排查。

**处理建议**：视频里**不要**使用这两段录屏作为「AI 真实回应」的证据。如需对话画面，改用 Remotion 代码绘制（见提示词里的备选方案），或后续在真机上补录。
