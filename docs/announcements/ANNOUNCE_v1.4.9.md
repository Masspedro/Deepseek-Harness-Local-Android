# DSH Mobile v1.4.9 更新公告

v1.4.9 上架喵～ 这一版全在治「启动」这一类毛病，其中最关键的一个是社区朋友帮忙修的。

## 🔴 重启后一直卡住 —— 修好了

有宝宝反馈：点「重启」之后一直停在「正在启动」，等多久都不动，只能杀 App 重来。

真凶是个标志位没复位。`stop()` 的时候把「正在停止」置成了真，但 `start()` 的时候忘了清掉 —— 于是新拉起来的监督循环第一轮就判断「该停了」，一次都不执行，界面永远停在「启动中」。

影响比想象的大：**任何一次停止**（后台被系统回收、通知栏退出、切权限模式）之后，这个进程里就再也启动不了引擎，只能杀 App。

**这个修复是群友 @henryz78 找到的。** 他不仅定位了根因，还多发现了一层：旧循环被取消是异步的，而异常捕获会把「取消」也一起吞掉，于是旧循环可能在复位之后继续跑完收尾，把新循环刚设的状态覆盖成「退避中」。所以现在退出判断会同时检查协程还活着没有。

我这边实测：连点三次重启，分别用 10.2 秒、13.2 秒恢复，日志记录完整。旧代码第一轮就会卡死。

## ⏱ 等几十分钟都进不去 —— 也修了

这个的原因不是单个 bug，而是几层自动修复各管各的、**加起来没有总预算**。算一下就明白：

```
每轮 = 45s 健康检查 + 20s 插件探针 + 退避
14 轮 ≈ 21 分钟     20 轮 ≈ 30 分钟
```

触发路径是「插件检测异常 → 摘掉插件 → 重启」，而旧代码在这里把退避计数**重置**了、当轮**没有延迟**、还**不计入**重启上限，于是能无限循环。

现在的做法：

- 加了个 **5 分钟总时限**，超时直接告诉你「启动失败」并给出排查建议，不再后台空转；
- 插件自动隔离的重启有了退避、最多 3 次，超了就停在「能用但降级」的状态；
- 成功进入健康状态后重置额度 —— 只约束「这一次启动」，不影响一直开着的设备。

## 🛡 三处「无限等待」加了超时

这三处比无限重试更糟，因为会让启动流程**永久停住**，连日志都不写：Shizuku 命令执行、Root 模式启动前备份、端口清理脚本。现在分别有 10 秒 / 60 秒 / 3 秒的预算，超时就放弃这一步继续往下走。

## 🔧 corepack 入口被覆盖

有位用户报得很准：`corepack` 命令报语法错误，直接执行会无限自循环。

真因挺有意思 —— 不是判断逻辑写错，而是**硬链接写穿**。Termux 的 npm 把 `bin/corepack` 硬链接到 `dist/corepack.js`（同一个 inode），而构建脚本用 `cat > bin/corepack` 生成启动器，shell 的 `>` 是**截断已有文件**而不是新建，于是把源 JS 一起覆盖成了 shell 脚本。

这也解释了为什么只有它一个坏：其余 6 个（npm / npx / pnpm / pnpx / yarn / yarnpkg）的 bin 和 dist 不共享 inode。

三层都修了：构建期先断链再写并校验、运行期自动检测还原、两份源运行时产物就地修复。

## 🖴 Root 模式新增重要提示

开 Root 时的第二次确认里，现在明确写了：

> - 不要**在应用目录或工作区目录里手动改动、移动、删除文件；
> - root 写出的文件属主是 root、权限收紧，App 自己随后读不了 —— 表现就是「插件加载失败」「引擎起不来」，往往只能清数据；
> - 你自己的文件放在**外部文件夹**（比如 `Documents/`），让 AI 在那里干活；
> - 要改应用内的东西，用应用自己的设置或插件，别用 root 文件管理器。

## 📝 Agent 说明修正

原来写的「不要安装 glibc/native 二进制」容易被理解成原生模块完全不能用。现在分成两句：glibc 预编译包❌不行，**源码编译✅可以**（有人实测 better-sqlite3 编译成功）。

## ⚠️ 两个已知问题（本版未修）

- 日志里会周期性出现 `/plugins/events` 的 `ERR_FAILED`。这是上游的**热重载端点**，生产环境不启用，前端仍在探测，不影响使用。
- `getJsStatus` 未捕获异常来自**第三方插件**，我们代码里没有这个符号。
