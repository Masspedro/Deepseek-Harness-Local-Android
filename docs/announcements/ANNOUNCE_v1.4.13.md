# DSH Mobile v1.4.13 更新公告（紧急）

**如果你在用 PTC 模式，请尽快更新。** v1.4.12 把它弄坏了，这版修好了。

## 🔴 PTC 模式报 libz.so.1 not found

**现象**：1.4.12 之后用 PTC（`run_code`）会报

```
CANNOT LINK EXECUTABLE ... library "libz.so.1" not found
```

引擎本身能正常启动，只有 PTC 跑代码的子进程起不来。

## 原因（是我的锅）

安卓上没有 `ldconfig`，引擎的 node 靠 `LD_LIBRARY_PATH` 找 `libz` 这类库。而 PTC 启动子进程时会把环境变量几乎全清空，只留一份白名单——那里面原本没有这个变量，所以子进程找不到库。

这个问题我们在 1.4.9 修过。但 1.4.12 我把打包切到了「去重后的运行时」，**那份包是在加这个补丁之前生成的**，于是补丁整个丢了，老问题原样回来。

更该骂的是：补丁只存在于某一个包里，**没有接进打包流程**。所以一换源包就静默消失，而且编译、测试全绿，根本看不出来。

## 修了什么

**补丁接进构建了**：每次打包都会检查那两处改动在不在，缺了自动补上；补完还缺就**直接中止构建**，不让坏包流出去。

**验证方式**：在模拟器里做了对照实验——

| 环境 | 结果 |
|---|---|
| 带 `LD_LIBRARY_PATH` | 正常执行 ✅ |
| 不带 | `libz.so.1 not found` ← 正是你报的错 |

也就是说，这个变量在不在，就是这个报错的开关。另外也验证了构建流程：故意换回没打补丁的包，构建会自动补上并打日志。
