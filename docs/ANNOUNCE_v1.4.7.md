# DSH Mobile v1.4.7 更新公告

宝宝们久等啦，v1.4.7 已经上架喵～ 这一版主要治三个「老毛病」，另外还收了社区贡献的一个渲染修复。

## 🩹 三个重点修复

**① 恢复对话后重启又变空 —— 修好了**

有宝宝反馈：恢复完对话，重启 App 一看工作区还是空的，以为历史被删了。

真凶不是恢复功能没干活，是**引擎在退出时把旧快照写回去了**。恢复写进去的登记，还没来得及保存就被引擎覆盖掉。

现在改成「先停引擎 → 等落盘 → 再写注册表 → 最后拉起来」，写之前还会自动备份一份 `workspace.json.before-recover`，写之后留一个戳方便排查。重启后还会自检一次：如果期望的会话不在，会明确告诉你，而不是假装成功。

**② 目录选择器「装好第一次能用，之后就不行」**

就是那个 `directoryPickerController is unavailable` 报错。有用户给了一份非常完整的定位，结论很清晰：

原本挂的 `directory-picker-auto` 是靠运行时动态挂载的，而那段代码一个进程只跑一次。只要哪一步抛错，`directoryPicker` 这个服务在整个进程里就再也不存在了，日志里还一个字都不留。

而它在 Android 上的探测结果其实是**固定的**（Termux 的 node 报 linux、没有图形环境、没有 zenity/kdialog → 永远走 browse），所以现在直接声明 browse 版本：少一条会断的链，行为一模一样。

**③ PTC / run_code 找不到 libz.so.1**

连续 7 天反馈的那个问题。之前的修补只把 `LD_LIBRARY_PATH` 加进了白名单，但父进程自己没设这个变量时，白名单等于放行一个空值，子进程照样拿不到库路径。

这次改成从 worker 自己的可执行文件位置反推引擎根目录，**无条件注入** `<引擎>/lib:<引擎>/usr/lib`，不再依赖继承。

## 🖼️ 登录弹窗渲染错位（社区贡献）

感谢 @skynit！首次启动（还没登录）时那个「开始使用」弹窗被拉成很扁的一条、标题没了、按钮只剩一个字，这个 bug 现在修了。

根因是缩放的时机：页面已经按 100% 画完了，才去改视口缩放，WebView 把部分图层留在旧栅格里，于是卡片背景、文字、按钮各用各的缩放。

现在改成**先把视口定好、再收启动遮罩**，并且在遮罩之下强制重绘一次整页。120ms 在遮罩最短等待（700ms）之内，你完全看不到这次刷新。

> ⚠️ 说明一下：这项修复贡献者那边完成了编译验证，但**没来得及真机回归**（提交时设备不在线）。如果你还能看到错位，麻烦在群里说一声，并帮忙看下 `engine.log` 里有没有 `reraster:` 这一行——有这行说明流程走到了，没这行说明压根没触发。
